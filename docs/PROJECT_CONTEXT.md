   15 сцен, 3D, режим докладчика, QA-скрипты, скриншоты. Коммит `01a03f6`.

4. **PR #3** — **пульт докладчика на телефоне** (QR-код, `api/remote`) и **облегчённый режим
   анимаций для телефонов**.
5. **PR #4** — в команду добавлены Зилола Фарходова и Юлиана Истратова; текст выступления
   переведён на «мы».
6. После PR #4 к проекту подключён **Upstash Redis** — пульт на сайте работает через Redis
   (`/api/remote?health=1` → `{"ok":true,"store":"redis"}`), сквозной тест на рабочем сайте 29/29.

Все PR сливались squash-слиянием в `main`; каждый push в `main` публикуется на Vercel автоматически.

### Ключевые цифры проекта (единый источник — `src/data/project.ts`)

Проект «FootureX MVP» — запуск игры FootureX в Telegram (Этап 1 · IT + Game). Цифры взяты из
внутреннего бэклога FootureX (документ BX-016); после PR #1 они публичны — пользователь это принял.

- Срок 6 месяцев = 12 спринтов по 2 недели; бюджет команды $5 000/мес
  (ставки 1 900 / 1 700 / 700 / 700).
- WBS: 4 результата (platform, game, economy, growth), пакеты E1–E13 = **176 идеальных человеко-дней**;
  задел L1 «базовые лиги» (11 ид, спринт 10).
- Ёмкость команды 192–216 ид → загрузка 81,5–91,7 %, буфер 16–40 ид.
- Вехи M1–M5 на спринтах 4/6/8/10/12; цели MAU: 1 200 → 9 000 → 15 000.
- Бюджет: базовый план **$33 900** (команда 30 000, инфраструктура 900, маркетинг 3 000)
  + управленческий резерв 10 % **$3 390** = **$37 290**.
- Риски R1–R7, оценка = вероятность × влияние (≥15 высокий, ≥8 средний).
- Контроль: SPI ≥ 0,95, CPI ≥ 0,95, стабильность 99,5 %, рост до 15 тыс. игроков.

Согласованность цифр проверяет `npm run test:sums` (`scripts/check-project.mjs`).

### Как устроен переход
Команда «далее» блокирует навигацию до конца перехода (двойной клик не пропускает сцены);
текущая сцена уходит в глубину, камера перелетает по дуге (1,25 с), новая сцена появляется,
после остановки камеры сцена получает `ready` и запускает графики. `prefers-reduced-motion`
заменяет всё короткой сменой прозрачности.

### Бренд
Шрифты Zen Dots + Poppins; у них нет кириллицы, поэтому для русского текста — Unbounded и
Montserrat (вшиты через @fontsource, интернет на защите не нужен). Электрический синий
(#2550FA / #2593FA), тёмный фон, стекло (glassmorphism). Оригинального логотипа в файлах нет —
показывается шрифтовой знак FOOTUREX; чтобы поставить настоящий логотип, положите SVG в
`public/brand/` и укажите путь в `ORIGINAL_LOGO_SRC` (`src/components/brand/brand.ts`).

## 6. Пульт на телефоне (PR #3)

**Как пользоваться:** на ноутбуке открыть сайт → **P** → отсканировать QR-код телефоном
(или открыть `footurexpptx.vercel.app/?speaker=1` и ввести 6 цифр). Окно с QR закроется само,
зелёная точка на кнопке — телефон на связи.

**На телефоне:** крупные «Назад / Далее» внизу, общий таймер с подсказкой темпа, таймер сцены,
текст выступления с кнопкой размера **Aa**, список сцен в шторке, альбомная раскладка, экран не
гаснет (Screen Wake Lock), таймер и подключение переживают перезагрузку. Без презентации окно
работает автономно — для репетиции.

**Как работает:** телефон и ноутбук встречаются в «комнате» (6-значный код) на ретрансляторе
`api/remote`: презентация публикует номер сцены и забирает команды, телефон читает номер сцены
и отправляет команды; оба опрашивают сервер раз в 0,4–0,7 с (WebSocket не нужен). Передаются
только номер сцены и команды; комната живёт 6 часов; команды старше 8 с отбрасываются.

**Хранилище:** функция берёт `KV_REST_API_URL` + `KV_REST_API_TOKEN` (их создала интеграция
Upstash в Vercel) или `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`; без них — память
экземпляра функции (работает, но может терять связь). Сейчас подключён Upstash — всё в порядке.
⚠️ Нужен именно **Upstash** (REST API). «Redis» от Redis Cloud в маркетплейсе Vercel не подходит:
у него только адрес `redis://`, а он ещё и платный.

**Где работает:** Vercel — да; `npm run dev -- --host` / `npm run preview` на ноутбуке — да, в одной
Wi-Fi-сети (открыть презентацию по сетевому адресу ноутбука); Netlify / Cloudflare / флешка — нет
(окно «Пульт» само об этом скажет, остаётся окно докладчика S).

Предпросмотры Vercel (адреса веток) закрыты входом в Vercel — с телефона пульт проверять на
основном сайте.

## 7. Облегчённый режим для телефонов (PR #3)

Телефон = сенсорный экран без мыши и короткая сторона ≤ 600 px (`src/app/deviceTier.ts`,
`<html data-perf="low">`). Ноутбук и проектор работают как раньше.

- 3D: плотность пикселей ≤ 1,25 (адаптивно до 0,75), без сглаживания, меньше частиц и зданий,
  облегчённые прожекторы; полная частота только во время перехода, в покое 30 кадров/с
  (`FrameGovernor`).
- Шейдеры всех объектов компилируются заранее (`ShaderWarmup`, на всех устройствах).
- Стекло без `backdrop-filter`, короткий переход (≈0,9 с) без масштабирования, без вечных
  SVG-вращений и анимированного blur.
- Замер (`node scripts/perf.mjs`, эмуляция телефона, программный WebGL): кадров в 2–2,7 раза
  больше, длинных задач в переходах в 4–6 раз меньше. На реальном телефоне не измерялось.

## 9. Публикация

- Vercel собирает каждый push: `main` → https://footurexpptx.vercel.app/, ветки → защищённые
  предпросмотры. Конфигурация — `vercel.json` (framework vite, `npm ci`, `dist`, регион `fra1`,
  кэш `/assets`).
- Запасные конфигурации: `netlify.toml`, `public/_headers` (Cloudflare Pages) — без пульта.
- Переменные окружения Vercel: `KV_REST_API_URL`, `KV_REST_API_TOKEN` (и другие от Upstash) —
  созданы интеграцией автоматически; значения никуда копировать не нужно.
