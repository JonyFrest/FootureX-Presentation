# FootureX Presentation OS — руководство разработчика сцен

Проект: интерактивная 3D-веб-презентация «Управление проектами FootureX Uzbekistan»
(защита университетского проекта, TIUE, дисциплина «Управление проектами», 10 минут, 15 сцен,
язык — русский). Основной формат — проектор/ноутбук 16:9 (1920×1080, 1600×900, 1366×768),
плюс телефоны.

## Архитектура (уже готова — не меняйте без согласования)

```
src/app/            App, Stage (переходы GSAP + параллакс + клик/свайп), store (zustand), клавиатура, окно докладчика
  remote/           пульт на телефоне: окно с QR-кодом (RemoteDialog), генератор QR, клиент ретранслятора
  speaker/          окно докладчика: раскладки SpeakerDesktop / SpeakerMobile, синхронизация, таймер
api/remote.ts       ретранслятор пульта: функция Vercel; в `vite dev`/`vite preview` — тот же код через плагин
src/components/
  scene/            SceneFrame, SceneHeader, Reveal, useScene()  ← используйте в каждой сцене
  ui/               Glass, Stat, CountUp
  nav/              NavBar (низ по центру), TopBar, SceneMenu
  backdrop/         3D-фон / CSS-фон + затемнение
  brand/            BrandLogo
src/three/          3D-мир (камера, стадион, город, объекты сцен)
src/data/scenes.ts  метаданные 15 сцен (порядок, камера, затемнение)
src/data/project.ts ЕДИНЫЙ источник данных проекта: устав, WBS, вехи, RACI, стейкхолдеры, бюджет, риски, контроль
src/scenes/SceneNNName.tsx   точка входа сцены (default export), регистрируется в registry.ts
src/styles/index.css         токены, типографика (.t-display .t-h1 .t-h2 .t-h3 .t-body .t-small .t-micro .t-stat .t-eyebrow), .glass, .chip
```

Слои: 3D-canvas (фон) → слой контента (HTML, ваша сцена) → навигация. Весь важный текст —
настоящий HTML. Не помещайте интерфейс в canvas, не используйте `position: fixed` в сценах.

### Где что лежит
- Сцена — `src/scenes/SceneNNName.tsx` (default export) и при необходимости папка `src/scenes/sNN/`.
- Новая сцена: добавьте метаданные в `src/data/scenes.ts` и загрузчик в `src/scenes/registry.ts`.
- Все цифры проекта берите из `src/data/project.ts` и считайте кодом — не прописывайте итоги вручную.

## API сцены

```tsx
import { SceneFrame, SceneHeader, Reveal, useScene } from '@/components/scene';
import { Glass, Stat, CountUp } from '@/components/ui';

export default function Scene09Workforce() {
  const { ready, active, reducedMotion } = useScene();
  return (
    <SceneFrame justify="center">            {/* безопасная зона: верхняя панель + нижняя навигация */}
      <SceneHeader title="Штатное расписание" lead="..." />   {/* подпись «09 · Workforce Planning» ставится сама */}
      <Reveal delay={0.2}> ... </Reveal>      {/* каскадное появление при входе сцены */}
      <Reveal waitReady> ... </Reveal>        {/* появление после остановки камеры */}
    </SceneFrame>
  );
}
```

- `active` — сцена текущая (с начала перелёта к ней). `ready` — камера остановилась, контент
  читаем: **запускайте анимации графиков, счётчиков, потоков только по `ready`**.
- `reducedMotion` — при `true` никаких движений: показывайте финальное состояние сразу.
- `CountUp`/`Stat` сами ждут `ready`.
- Анимации — `motion/react` (Framer Motion API) или GSAP. Без бесконечных агрессивных анимаций;
  допустимы медленные мягкие циклы (бегущие точки потока данных), отключаемые при reducedMotion.

## Дизайн-система FootureX (брендбук)
- Тёмная технологичная база, электрический синий. Цвета (Tailwind): `bg-ink #0B0F0E`,
  `bg-deep`, `bg-surface #0E1629`, `border-line #273B51`, `primary #2550FA`, `secondary #2593FA`,
  `highlight #8EB4FF`, `ice #DCE7FF`, `soft #B8C1D4`, `mute #8A93A6`. Градиент бренда
  `linear-gradient(135deg,#2593FA,#2550FA)` (`var(--grad-brand)`, `.text-brand-gradient`, `.text-gradient`).
  Для графиков — `chartPalette` из `src/styles/tokens.ts`. Других акцентных цветов не вводить
  (никаких зелёных/красных/оранжевых). Статус «план» — пунктирная обводка (`.chip.chip-plan`), а не новый цвет.
- Шрифты: `font-display` (Zen Dots; для кириллицы автоматически Unbounded) — заголовки, цифры, латинские
  подписи; `font-sans` (Poppins; для кириллицы Montserrat) — текст и интерфейс. Других шрифтов нет.
- Размеры текста ТОЛЬКО через классы шкалы `.t-*` (они масштабируются от кадра 16:9 через `--u`).
  Отступы — `var(--gap-1..4)`. Минимум для читаемого текста — `.t-micro` (≥ 11.5px).
- Поверхности: `.glass` / `.glass-strong` (компонент `Glass`), скругления `var(--radius-md)`.
  Не больше ~10 стеклянных панелей на сцену (backdrop-filter дорог).
- Hover: интерактивные элементы слегка приподнимаются (`glass-hover` или `hover:-translate-y-0.5`)
  и подсвечиваются синим. Фокус с клавиатуры обязателен (используйте `<button>`).
- **Композиция: один главный смысловой акцент на экране, 1–3 коротких текстовых блока.**
  Содержание — через инфографику, диаграммы, схемы, таймлайны, крупные числа. Без «стен текста».
- Без эмодзи. Язык — русский; короткие латинские подписи в стиле FootureX допустимы.

## Навигация и интерактив
- Клик по свободной области сцены = «Далее». Клик по `button`, `a`, `[role=tab]`,
  элементам с `data-interactive`, графикам Recharts — НЕ переключает сцену.
  Поэтому: всё, на что зритель кликает/наводит, делайте `<button>` или помечайте `data-interactive`.
- Стрелки ←/→, пробел, Home/End заняты презентацией. Не перехватывайте их в сценах.
- Подсказки при наведении должны работать и с клавиатуры (focus) и на тач-экранах (tap = выбрать).

## Адаптивность (обязательно проверить)
- 1920×1080, 1600×900, 1366×768: вся сцена помещается в кадр без прокрутки, ничего не наезжает
  на верхнюю панель и нижнюю навигацию (это гарантирует `SceneFrame`, если контент не выше кадра),
  нет обрезаний и наложений. 1366×768 — самый тесный случай по высоте (~600px под контент).
- Телефон 390×844 (и альбомный 844×390): раскладка перестраивается (одна колонка, карточки вместо
  таблиц, вкладки вместо панелей), а не просто уменьшается. Внутри `SceneFrame` на телефоне работает
  вертикальная прокрутка. Хук `useIsCompact()` из `@/hooks/useMediaQuery` — компактная раскладка.
- Никакой горизонтальной прокрутки.

## Проверка своей работы (обязательно, фактически, а не на словах)
1. `cd /home/user/footurex-presentation && npx tsc -b` — без ошибок.
2. Запустите `npm run dev` — http://localhost:5173/ (сцена N: `?scene=N`).
3. Скриншоты: `node scripts/screenshots.mjs --scenes 8,9 --sizes 1920x1080,1366x768,390x844 --out qa-output/<ваше-имя>`
   (`--reduced 1` — режим reduced motion). Откройте PNG инструментом Read и критически оцените:
   читаемость, наложения, обрезания, баланс композиции, соответствие бренду. Исправляйте и повторяйте.
4. Для проверки hover/кликов можно написать свой одноразовый Playwright-скрипт в `qa-output/`
   (используйте `launch()` и `openScene()` из `scripts/browser.mjs`).

  (планируется); Этап 3 — Stadium + FootureX City (планируется).

  спринт-бэклог FootureX (BX-016): 6 месяцев, 12 спринтов по 2 недели, 13 эпиков (176 ид),
  бюджет команды $5 000/мес, вехи, критерии приёмки, риски. Разбивка бюджета, оценки рисков,
  RACI, стейкхолдеры и KPI — плановые допущения; на слайдах помечайте «план».
